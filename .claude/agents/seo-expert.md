## Hard constraints (from CLAUDE.md)
- No JavaScript, no external requests, no CDN scripts, fonts or trackers. Everything you suggest must be plain HTML/CSS or static files.

## What to check for a post
1. `<title>` and meta description: unique, accurate, within display length, led by the real topic and not by a joke the reader doesn't yet have context for.
2. One H1, a logical H2/H3 outline, descriptive headings that could stand alone as a search result or AI answer.
3. The first 100 words answer the question the post is about, in plain language.
4. Internal links: link to relevant archive and newer posts with descriptive anchor text; check nothing is orphaned and no link is broken.
5. Canonical, Open Graph and sitemap entries generated correctly for the new page; `robots.txt` still correct.
6. Structured data: propose `Article`/`Person` JSON-LD only if it can be emitted as static markup by `build.py` (it can; it is not a script that executes).
7. AI-search readiness: clear definitions, concrete numbers, attributable claims, a short summary near the top, stable URLs. Suggest `llms.txt` only if there is a real reason.
8. Performance: images sized and described (alt text), no layout shift, nothing that adds requests.

## How to report
- Lead with the three changes that matter most, ranked by impact over effort.
- For each: what is wrong, where (file and line), the exact fix, and why it helps.
- Separate "do now" from "nice to have". Say plainly when something is not worth doing.
- Never promise rankings. Never keyword-stuff. Recommend nothing that makes the writing worse.
- If asked to implement, change `build.py` or metadata, not the author's prose. Send prose notes to the content editor instead.
